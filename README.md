# 万卷挑一 · 好书一下

从豆瓣图书标签页抓取书目的本地小项目，配一个可筛选的好书榜网页。个人自用，请保持默认的低抓取频率。

## 目录结构

```
wanjuan/
├── cli.py               统一命令行入口
├── serve.py             本地网页预览服务器（必须用它打开，双击 index.html 加载不了模块）
├── run_scale.sh         两阶段扩量（113 标签×按评分 → 145 标签×按热门）
├── run_monthly.sh       月度数据队列：月度榜 → 新书速递 → export → 补标签 → 补漫画
├── run_rest.sh          收尾队列：漫画标签 → 300 本原文摘录 → export
├── spider/
│   ├── fetcher.py       HTTP 层：限速 3~6 秒/请求、重试、403 冷却
│   ├── parsers.py       豆瓣页面解析（列表页 / 详情页 / 月度榜 / 新书速递 / 原文摘录）
│   ├── store.py         data/douban_books.json 数据库（文件锁 + 原子写，见下方「并发」）
│   └── exporter.py      导出 web/books_data.json

    ├── index.html          页面骨架（只放结构，不含内联脚本和样式）
    ├── books_data.json     export 生成的真实数据（前端 fetch 读取）
    ├── css/
    │   ├── base.css        配色变量、排版基调
    │   ├── layout.css      页首 / 搜索 / 筛选 / 排序 / 列表 / 分页 / 新书雷达
    │   └── modal.css       详情弹窗
    └── js/
        ├── config.js       常量：默认条件、分页、排序项、好书指数与雷达参数
        ├── utils.js        DOM 兜底绑定、格式化、确定性随机
        ├── demo-books.js   内置演示数据（读不到真实数据时兜底）
        ├── data.js         数据装配：fetch books_data.json，失败退回演示数据
        ├── state.js        筛选状态单例 + URL 读写 + 表单回填
        ├── metrics.js      好书指数、雷达分、月度榜/新书池、筛选、排序（纯函数）
        ├── render.js       渲染协调器：状态 → 视图（书目 / 雷达）→ 各面板
```

### 为什么这样拆

- **改一处只动一个文件**：调默认筛选条件改 `config.js`；改排序规则改 `metrics.js`；改样式去 `css/`；调交互去 `events.js`。
- **应用代码不再住在 `index.html` 里**：外部预览/编辑工具回写这个文件时，最多注入几个属性，不会再把整个应用搞挂。
- **`metrics.js` 是纯函数**，不碰 DOM，想核对好书指数或筛选逻辑不用开浏览器。
- **`data.js` 有兜底**：读不到 `books_data.json` 时（比如还没跑爬虫）自动用 92 条演示数据，页面照样能看。

## 使用

```bash
cd wanjuan

# 1) 按标签抓书目（列表页就带评分和人数；「评价人数不足」的条目也会入库）
python3 cli.py list --tags 小说,历史,科幻,推理,心理学,经济学,哲学 --pages 40

# 2) 抓豆瓣「N月热门图书榜」+「新书速递」——月度视图的数据源（每月跑一次攒历史）
python3 cli.py chart && python3 cli.py latest

# 2.5) 抓「原文摘录」——经典段落 + 页码引用，进详情弹窗（每本 1 次请求）
python3 cli.py quotes --limit 300

# 3) 给高分书补详情页（标签、简介、星级分布；也补列表页「载入中」的评分）
python3 cli.py detail --limit 800

# 4) 导出网页数据
python3 cli.py export

# 5) 本地看网页（ES Module 必须走 http，双击 index.html 打不开）
python3 cli.py serve          # 打开 http://localhost:8000

# 随时看进度
python3 cli.py status
```

## 网页用法（web/index.html）

顶部导航两个视图，筛选条件与关键词搜索在两个视图里都生效：

**书目（默认）**
- 打开即是可信好书榜：最低分 8.5、最少评价 1000 人、已合并同书版本
- **最低分**：拖动滑块（0~10，步进 0.1），右侧数字框也能直接输入，两者双向同步
- 筛选条件实时生效，排序栏右侧显示当前条件与结果数；数字框支持回车确认
- 其他开关：最少评价、年份区间、排除标签（如「漫画」）、合并同书版本、含漫画与绘本
- 「恢复默认」一键回到 8.5 分 / 1000 人 / 合并版本

**新书雷达**（数据来自豆瓣的月度接口，`cli.py chart` / `cli.py latest`）
- **豆瓣月度榜**：豆瓣官方的《N月热门图书榜》，直接用豆瓣给的名次排，
  带名次涨跌（升红降绿）和「连续上榜 N 个月」；「历次」= 每本书最新一次上榜
- **新书速递**：按**出版年月**看新书（标签页只给年份，这里给到月），雷达分排序
- 雷达分用 **m=150** 而不是主榜的 1000：新书评价人数天然少，沿用主榜权重
  会把所有新书拉平到 8.05 附近，排不出高低（页面底部有说明）
- ⚠️ 豆瓣只发布**当月**榜单，往期取不到接口——所以要每月跑一次
  `cli.py chart && cli.py latest` 自己攒历史，攒得越久月度对比越有用

- **详情弹窗的「原文摘录」**：豆瓣读者标注的经典段落（`cli.py quotes` 抓取，
  按赞数取前几条），朱批样式排印、附「引自第 N 页」

- 两个视图的状态都会写进 URL（`?view=radar&rm=latest&month=2026-08&rv=50`），可直接分享

## 能抓多少（实测结论）

豆瓣图书的可枚举入口就是标签页，而**每个标签页每种排序只开放前 1000 本**（`start=1000` 起返回空）。
标签云共 **145 个标签**，「按评分」和「按热门」两套排序的前 1000 本几乎不重合（实测前 20 本重合 0 本）。
标签之间重叠也很低：**82% 的书只属于 1 个标签**，边际产出稳定在 ~810 本/标签。

| 抓法 | 请求数 | 耗时（3~6 秒/次） | 预期规模 |
|---|---|---|---|
| 113 个未抓标签 × 按评分 | 5,650 | ~7 小时 | 累计 7~8 万 |
| 再加 145 个标签 × 按热门 | 7,250 | ~9 小时 | 累计 10~13 万 |
| 全部补详情页（简介/星级分布） | 每本 1 次 | 10 万本 ≈ 5 天 | 字段覆盖率 100% |

**上限就是 10~13 万**。要再往上只能按 subject id 探测号段（约 4000 万个号），
200 万本需要 200 万次以上请求 ≈ 100 天，且必然触发反爬，不建议。

```bash
# 一键跑完上面两个阶段（约 16 小时，建议夜里挂机）
./run_scale.sh
```

> 注意：对榜单的实际价值是递减的。目前 2.9 万本里 ≥1000 人评价的只有 4,722 本，
> 默认视图出 2,151 本；即使拉到 13 万本，榜单**前 20 名基本不会变**。
> 数据量的收益主要在长尾检索（冷门题材、冷门作者），不在主榜。
> 相比之下，详情页覆盖率才是体验瓶颈——现在只有 4% 的书有简介和星级分布。

## 并发写入（曾丢过数据）

同一时刻跑两个抓取任务时，旧的 `save()` 是**整库覆盖写**：两个进程各持一份自己启动时的
快照，后写的那个会把先写的整库顶掉。这次就把「漫画/绘本/杂志/日漫/轻小说」那轮抓到的
约 3,800 本一次性抹掉了（数据库里这 5 个标签变成 0 本）。

现在 `spider/store.py` 的 `save()` 分三步：

1. 拿 `data/douban_books.json.lock` 的排他文件锁（`fcntl.flock`），跨进程互斥；
2. **先把磁盘上的库并回内存**（标量「有值优先」、tags 取并集），再整体写回；
3. 临时文件 + `os.replace` 原子替换。

并回磁盘这一步是关键——它保证「磁盘 ∪ 内存」都写出去，既不丢别人写的，也不丢自己写的。
双进程各写 120 条的压力测试结果为 240/240，一条不丢。

另外 `cli.py list` 从「每页存一次」改成**每 5 页存一次**：库已有 9MB，
每页都整库写回会让抓取慢一倍以上。

`run_comics.sh` 就是用来补回被抹掉的那 5 个标签的——它会先等当前抓取进程退出
（正在跑的那个进程用的是旧代码，仍会覆盖），再按「评分」和「热门」两套排序各补一轮。

## 说明

- **默认版面条目**：豆瓣列表页里「评价人数不足」或评分「载入中」的条目会以 `rated=false` 存入数据库；`detail --all` 可去详情页补真实评分，补不到就不上榜单。
- **防封**：相邻请求随机间隔 3~6 秒；403/418/429 自动冷却 30 分钟再试；数据按豆瓣 subject id 去重，中断后重跑自动续。
- **无年份的书**：列表页拿不到出版年、又没补详情的书，在「最新出版 / 最早出版」里统一排到最后，不会因为 `y` 为空被当成公元 0 年排到最前。
- **改端口**：`python3 serve.py --port 8777` 或 `python3 serve.py 8777` 都行。
- **断点续抓**：`list` 重跑同一标签会跳过已入库书目（只更新评分人数）；`detail` 只补缺简介的。
- 好书指数 = v/(v+m)×评分 + m/(v+m)×C，m=1000，C≈8.05（IMDb Top 250 同款贝叶斯公式）。
- 数据来自豆瓣读书公开页面，仅供个人使用，与豆瓣无关联。
